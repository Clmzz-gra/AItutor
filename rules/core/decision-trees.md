# 规则决策树（decision-trees）

> 所有规则必须是**显式的流程或决策树**，AI 按此确定性执行。
> 核心规则 · 学科无关。
> 操作规则见 §8；文章类型见 `asset-spec.md`；生成方式见 `article-generation.md`。

---

## 1. 是否建 checkpoint / 是否成文决策树

> 设计原则：**AI 不做价值判断**；checkpoint 是安全默认，是否升级正式由用户确认。

```
对话中出现新内容？
│
├─ seed 已有？
│   └─ 是 → 只读引用（wikilink），不新建、不修改
│
├─ 纯闲聊 / 操作指令 / 一句话澄清？
│   └─ 是 → 不建 checkpoint，正常对话
│
└─ 新话题 / 新问题 / 新讨论 / 讲解 / 出题 / 作业？
    └─ 建 checkpoint（草稿文章，类型按 10 类标注）——不判断价值
        → git [TOPIC <文章名>][OPEN]
        → 收尾二选一：“收进资产，还是继续？”
        → 用户确认收进资产 → 升级正式文章 + git CLOSE
        → 用户选择继续 → 保持 OPEN
        → 用户选择关闭/放弃 → git CLOSE
```

补充：
- AI 可以在收尾时给出“建议升级”信号（产生了可复用理解 / 新概念 / 反例 / 用户说“记下来”等），但**最终是否成文由用户确认**
- “是否值得成文” = “是否值得从 checkpoint 升级为正式文章”，不是一开始判断值不值得记录

## 2. seed / personal 边界决策树

```
要写内容？
│
├─ 是 seed 已有 → 只读，不修改（只能引用）
├─ 是新增内容 → personal/
│   ├─ 笔记/节点    → personal/notes/
│   ├─ 论文/文献    → personal/papers/
│   ├─ 习题/作业/问题 → personal/notes/（按类型命名）
│   ├─ 演示工具     → personal/demos/
│   └─ 画像数据     → personal/profiles/
└─ 是初始化 / 现成 seed → seed/（每学科只初始化一次，全量）
```

## 3. 文章拆分 / 合并决策树

```
一篇文章含多个问题/主题？
│
├─ 问题间强关联？
│   ├─ 是 → 合并为一篇（不拆）
│   └─ 否 → 拆分为多篇（内容不丢失，链接重分配）
├─ 多篇强关联 → 合并为一篇
└─ 单问题 → 一篇
```

## 3·5. 链接结构决策树（学科概览只连顶层，沿用）

```
要建立链接？
│
├─ 目标是学科概览？→ 不直连（学科概览只连顶层：章文章）
├─ 目标是章文章？→ 直连（如 [[Ch3 测度论]]）
├─ 目标是相关概念/节/其他文章 → 直连
└─ 目标不存在 → 先创建或提示用户，不建坏链
```

> 链接本身不带语义：入链/出链/双链只是方向；使用场景由规则限定（外部文献/作业挂知识点=入链，学生推导新增链回=出链，知识联系/复习依赖=双向）。

## 4. 讲解收尾流程（强制）

> **每次回复最后一句用二选一收尾**（导游口吻，不机械）：
> - 主句式：**「这段讨论，收进资产，还是继续往下聊？」**
> - 有未闭合 checkpoint 时：**「这段还开着 checkpoint，收进资产，还是继续？」**

```
讲解快结束（每次回复最后一句）
  → 二选一询问："这段讨论，收进资产，还是继续往下聊？"
  → 学生回答？
    ├─ 收进资产 → 按 asset-spec 升级为正式文章（git CLOSE）
    ├─ 继续往下聊 → 保持 checkpoint，继续讲解
    └─ 未回答 → 保持 checkpoint，下次再问
```

## 5. checkpoint / 话题生命周期（TOPIC OPEN/CLOSE，按文章名）

```
实质新话题出现（纯闲聊 / 操作指令除外，判定见 §1）
  → 建 checkpoint（草稿文章，按 10 类标注类型）
  → git [TOPIC <文章名>][OPEN]
  → 讨论/起草都在 checkpoint 内进行
  → 收尾询问 → 用户确认收进资产？
    ├─ 是 → 升级为正式文章 + git [TOPIC <文章名>][CLOSE]
    ├─ 继续 → 保持 OPEN
    └─ 放弃/删除/归档 → git [TOPIC <文章名>][CLOSE]
```

- **按文章名闭合**，不按主题
- checkpoint 属于资产，正式与否只是 tag，建文时定
- 正式文章全部由 checkpoint 升级而来，**不直接创建**

## 5·5. 新对话话题检查（强制）

> 开启新对话时，先查 git 记录，确认没有“开了没闭”的话题。

```
开启新对话
  → git log --grep "[TOPIC"   # 列出所有 OPEN/CLOSE 事件
  → 有 OPEN 且无对应 CLOSE 的话题？
    ├─ 是 → 列出未闭合文章名
    │     → 询问学生：继续 / 收进资产 / 关闭（放弃）
    │     → 处理后才开始新话题
    └─ 否 → 正常开始
```

## 6. 中断 / 恢复流程

```
学生离开
  → checkpoint 已提交（OPEN 保持）
学生回来"继续"
  → git log --grep "[TOPIC" 找未闭合话题（按文章名）
  → 列出 → 询问用户继续哪个
  → 恢复讲解（在对应 checkpoint 内继续）
```

## 7. 学习类型判定决策树（非互斥）

```
节点数 = 0？→ 无增量数据
深度≥4 且 密度≥0.5？→ 深挖型
节点≥20 且 深度≤2？→ 广撒网型
密度≥0.6？→ 关联型
深度≥3？→ 纵深型
以上都不满足？→ 均衡型
（符合条件的都算，非互斥）
```

## 8. 文章操作决策树

```
用户提出文章操作意图
  → 定位文章（名称 / 搜索 / 目录）→ 有歧义？→ 问用户
  → 判断操作：
    ├─ 创建     → 建 checkpoint（OPEN）→ 收尾确认后升级（CLOSE）
    ├─ 修改     → 改内容/updated → 改名需同步链接 → 检查坏链 → git
    ├─ 链接     → 按场景添加；目标必存在；学科概览只连顶层
    ├─ 删除     → 先提炼 → 清理入链 → 用户确认 → 删除 → CLOSE
    ├─ 归档     → 移入 _archive/ → 保留/改指向提炼摘要 → CLOSE
    ├─ 拆分     → 用户确认方案 → 建新文章 → 链接重分配 → 检查坏链 → git
    └─ 升级     → checkpoint → 正式文章（类型不变，仅 formal:true）→ CLOSE
  → 执行后坏链检查 → git 提交（信息含文章名）
```

**铁则**：
1. AI 不确定 → 一律咨询人类，不得擅自操作
2. seed 只读，操作只作用于 personal
3. 类型不变：升级只改 formal 状态，无类型转化
4. 删除/归档/拆分/改名必须先处理指向它的 wikilink
5. 无索引：定位靠 目录 + frontmatter + wikilink + 搜索 + git log
