# 资产类型与规范（asset-spec）

> 定义系统里"资产"（文章）的类型和每篇资产的规范。核心规则 · 学科无关。
> **资产 = 文章**，都属于资产层（`assets/`）。区别只在**正式 vs 临时**。
> 文章生成方式见 **`rules/core/article-generation.md`**。

## 一、文章类型（10 类内置，可扩展）

> seed 是目录（归属层），不是文章类型。讲解包是多文件展开（属于 note），不是文章类型。

| # | 类型 | 命名 | 说明 |
|---|------|------|------|
| 1 | 学科全景 | `学科概览.md` | 学科地图（seed 顶层） |
| 2 | 章 | `Ch{N} {章名}` | 章级文章（单文件，不叫讲解包） |
| 3 | 节 | `Sec{N.M} {节名}` | 分节笔记 |
| 4 | 概念 | `概念-{概念名}.md` | 概念节点 |
| 5 | 论文 | `论文-{标题}.md` | 论文 / 文献（放 `personal/papers/`） |
| 6 | 思考 | `思考-{主题}.md` | 反思 / 讨论沉淀 |
| 7 | 提问 | `提问-{问题}.md` | 学生提问（只积累问题，不转化为概念） |
| 8 | 习题 | `习题-{主题}.md` | 出题 / 习题 |
| 9 | 作业 | `作业-{主题}.md` | 作业 / 任务 |
| 10 | 问题 | `问题-{主题}.md` | 待解问题 |

> **checkpoint**：临时草稿/快照，`_checkpoints/{文章名}.md`；属于资产，正式与否只是 tag（建文时定）。
> checkpoint 文章末尾固定维护 **「未决问题」段**：讨论中提出但未解决的问题逐条登记（`- [ ] 问题（[[关联节点]]）`）；升级/关闭时未决问题不丢——并入正文对应字段（如思考的"待验证 / 待追问"）或升级为提问/问题文章。
> 为什么：对话随时会断，"问出去还没答的问题"是最易丢、最珍贵的状态——恢复对账从文件级细化到问题级。

### 一·五、文章类型扩展通道（二次开发）

> 新增文章类型是**核心规则扩展**，不是普通用户操作。必须按以下扩展点补齐，不能只改一个文件。

| 扩展点 | 位置 | 说明 |
|--------|------|------|
| 类型定义 | 本文件 §一 | 新增 `type` 值 + 命名规则 |
| frontmatter | 本文件 §三 | 类型特有字段（可选） |
| 结构模板 | `templates/{type}-template.md` | 新建对应模板 |
| 生成方式 | `rules/core/article-generation.md` | 生成依赖表新增一行 |
| 图谱配色 | `tools/graph-style/configure.py` | 新增 personal / seed 配色 query |
| 校验规则 | 本文件 §四 + `article-generation.md` | 该类型必填项 / 链接 / 校验 |
| 生命周期 | 默认沿用 `decision-trees.md` | checkpoint → 升级 → 维护 |
| 目录归属 | 本文件 §二 | 默认 personal；确属 seed 类型才放入 seed |

扩展流程：

1. 确认现有 10 类 + 讲解包无法表达该内容
2. 按上表补齐所有扩展点
3. 更新 README / 导航（如需要）
4. 登记到 `maintenance/registry.md`

> 新增类型默认使用 personal 高饱和配色；若作为 seed 类型，则使用 seed 低饱和配色。

## 二、目录约定（Obsidian 原生治理，无索引文件）

```
assets/{学科}/
├── seed/                 # 只读共享地基（初始化全量生成，每学科一次）
│   ├── textbook/         # 教材 OCR（不参与图谱）
│   ├── 学科概览.md
│   └── Ch{N} {章名}.md
└── personal/             # 学生增量（可操作）
    ├── notes/            # 章/节/概念/思考/提问/习题/作业/问题 文章
    ├── papers/           # 论文/文献
    ├── demos/            # 演示工具
    └── profiles/         # 学习画像数据
_archive/{学科}/          # 归档（不再活跃但有参考价值）
```

- 治理 = 目录 + frontmatter + wikilink + 搜索 + git log；**不设 `_index.md`**
- 定位文章：目录 / 搜索 / wikilink / git log

## 三、通用规范

### 1. frontmatter（必填）
```yaml
---
type: {10 类之一}
formal: true|false      # 是否正式（checkpoint 为 false）
subject: {subject-slug}
created: {YYYY-MM-DD}
updated: {YYYY-MM-DD}
tags: [math, {subject-slug}]
---
```

### 2. wikilink（必填）
- 每篇文章至少 1 个 wikilink（无孤立文章）
- 链接本身不带语义；使用场景由规则限定（见 `decision-trees.md` §3·5）
- 学科概览只连顶层（章文章）

### 3. 质量约束（学习类文章）
- 先定义再使用（新符号 + 自然语言读法）
- 每步有"因为"
- 反例强制（定义/定理后）
- 核心洞察收束

### 4. 生命周期
```
创建（checkpoint 草稿）→ 升级（正式文章）→ 维护（修改/链接/拆分）→ 归档/删除（git CLOSE）
```
- 正式文章全部由 checkpoint 升级而来，不直接创建
- **类型不变**：无类型转化；提问文章升级后仍是提问文章
- git：`[TOPIC <文章名>][OPEN]` / `[CLOSE]`

## 四、各类型结构（10 类细化）

> 通用 frontmatter 见 §三.1；每类必须满足 §三.2（至少 1 个 wikilink）。
> 以下“必填”为最低结构；具体内容遵循 `tutor` / `exercise-generator` 的质量约束。

### 1. 学科全景

```
# {科目名} — 学科全景
> 定位：这门课在学科版图里的坐标？

## 数学史背景
[时代背景 / 核心问题 / 关键人物]

## 发展脉络
[演变过程：关键转折点 / 重大定理的发现顺序]

## 当代应用
[在科学 / 工程 / 经济等领域的应用]

## 与其他科目的关系
[前置依赖 / 平行类比 / 后续延伸]

## Ch{N}: {章名}
[[Ch{N} {章名}]]  # 只列章标题，不展开下级
```

- **链接**：只连顶层章文章；不连节/概念
- **校验**：四要素齐全；无下级概念直链
- **模板**：`templates/overview-template.md`

### 2. 章

可选 frontmatter：`chapter: {N}`、`aliases`

```
# Ch{N} {章名}
> 教材：{教材名} / 定位：本章回答什么问题？

## 整体认知（章节地图）
[本章三块内容 + 依赖关系 + 学完应能回答的问题]

## 前置知识
[[前置章/节/概念]]（每个前置说明“这是为了……”）

## 主体
### {核心概念 1}
#### 动机
[为什么需要它]
#### 定义
[先定义再使用 + 自然语言读法]
#### 推导 / 证明
[每步有“因为”]
#### 反例
[条件不满足时结论失败的例子，强制]
#### 易错点
[常见错误]

### {核心概念 2}
[标准四层：整体认知→来龙→主体→去脉]

## 去脉 / 应用
[当代应用 / 跨领域解读 / 高层视角]

## 检验（可选）
> [!note]- 答案
> [折叠答案]
[自测题 3-5 道，至少 1 道动机复述题]
```

- **链接**：前置/后继章、学科概览、涉及节或概念
- **模板**：`templates/chapter-template.md`

### 3. 节

可选 frontmatter：`chapter: {N}`、`section: {N.M}`

```
# Sec{N.M} {节名}
> 定位：本节在章里的位置与作用。

## 来龙（为什么需要它）
- 类比已知：[与已有知识的联系]
- 解决新问题：[什么新问题推动了本节]
- 理论/应用需要：[为什么本节是必要的]

## 主体（核心内容）
### 定义
[先定义再使用 + 自然语言读法]
### 定理
[陈述 + 关键条件 + 证明概要]
### 反例
[定义之后强制正反例；定理条件不可少的反例]
### 例题
[完整走一遍：原始信息 → 公式代入 → 结果 → 结论]

## 去脉（学完去哪）
[当代应用 / 跨领域解读 / 高层视角]

## 防跳跃
- [可能需要展开的概念点，供后续追问]
```

- **链接**：章、前置/后续节、相关概念
- **模板**：`templates/section-note-template.md`

### 4. 概念

```
# 概念-{概念名}
- 定义：[一句话定义 + 自然语言读法]
- 正例：[一个典型例子]
- 反例：[强制；说明边界在哪]
- 边界情况：[容易混淆 / 条件不满足时]
- 关联：[[前置概念]] [[后续概念]] [[相关概念]]
```

- **链接**：至少 1 个相关概念/章/节
- **模板**：`templates/concept-template.md`

### 5. 论文

```
# 论文-{标题}
- 一句话：[解决什么问题 / 核心贡献]
- 来龙：[背景 / 问题动机]
- 主体：[方法 / 结果 / 贡献]
- 去脉：[局限 / 后续工作 / 与学习主题的关系]
- 关联：[[相关概念]] [[相关定理]]
```

- 复杂论文可用讲解包模式（见下“讲解包”）
- **模板**：`templates/paper-template.md`

### 6. 思考

```
# 思考-{主题}
- 触发：[什么场景/问题引发]
- 我的理解：[允许不全懂]
- 与已有知识的联系：[[相关概念]]
- 待验证 / 待追问：[未闭合的问题]
```

- **模板**：`templates/thinking-template.md`

### 7. 提问

```
# 提问-{问题}
- 问题：[一句话说清]
- 我的猜测（如果有）：[当前假设]
- 关联：[[相关概念]]
```

- 只积累有价值的问题；不转化为概念文章
- **模板**：`templates/question-template.md`

### 8. 习题

```
# 习题-{主题}
- 关联：[[相关知识点]]

## 题目
[单选 / 判断 / 填空 / 读表 / 计算 / 综合对比]

> [!note]- 答案
> [折叠答案]

## 考点标签
[关联文章 / 考点]
```

- 生成走 `exercise-generator` skill：只出题 + 答案折叠，不做检验
- **模板**：`templates/exercise-template.md`

### 9. 作业

```
# 作业-{主题}
- 来源：[教材 / 课堂 / 用户提供]
- 任务说明：[要做什么]
- 要求 / 截止（可选）：[如果用户提供]
- 关联：[[相关知识点]]（入链挂知识点）
- 完成情况：[由对话/内容记录，不建状态表]
```

- **模板**：`templates/homework-template.md`

### 10. 问题

```
# 问题-{主题}
- 问题描述：[清楚描述要解决的问题]
- 已尝试 / 约束：[做过什么尝试、有哪些限制]
- 关联：[[相关概念]]
- 待解状态：[由 git / 内容决定，不建状态表]
```

- **模板**：`templates/problem-template.md`

### 讲解包（多文件展开，属于 note，不是类型）

```
{主题} — 讲解包/
├── 00 整体认知.md     # 总览/目录
├── 01 …
├── 02 …
└── …
```

- 分篇用 wikilink 与首篇互链，不得有孤立分篇

## 五、归档 / 删除规则（先提炼、后删除）

```
这篇文章还要不要？
│
├─ 仍有参考价值、只是不再活跃
│   → 归档：移入 _archive/{学科}/（或 personal/archive/）
│   → git [TOPIC <文章名>][CLOSE]；保留或改指向提炼摘要
├─ 有价值片段可复用
│   → 先提炼进相关文章 / 节点
│   → 再归档或删除，链接改指向提炼后的文章
├─ 与现有文章重复
│   → 合并：关键内容并入目标文章，更新链接，删除本文
└─ 确认无价值
    → 删除：git 保留历史，发 CLOSE 事件
```

强制：
1. 先提炼、后删除（有价值内容必须落到其他文章/节点）
2. 先改链、后移除（清理指向它的 wikilink，避免坏链）
3. 文章变动必须 git 提交流水
4. 默认归档；删除是例外，需用户确认

## 六、节点类型与图谱操作

> 图谱节点 = 文章；wikilink = 边；Obsidian 原生展示。

操作集：创建 / 修改 / 链接 / 删除 / 归档 / 拆分 / 升级（详见 `decision-trees.md` §8）
- 定位正确、链接正常、seed 只读、类型不变、AI 不确定先问人
