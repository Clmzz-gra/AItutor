# 可视化交互生成 — 教学演示工具生成规范

> 版本 2.1 | 2026-08-31 | 在通用规范上新增**浏览器端可视化进阶拓展**（three.js / p5.js / d3.js）
> 本 skill 承载「生成教学演示 GUI 工具」的**通用规范**：结构（core/ui/utils 三层）+ 演示要素 + 界面要素 + 实验对比 + 验收标准。
> 学科/算法专属内容作为**拓展**，见文末「学科拓展」；高质感浏览器端演示见**拓展 C**。

## 定位

教学演示工具 = 用**可视化交互**让学生理解抽象概念/算法/定理的独立可运行 GUI 应用。
本 skill 把这类工具的**通用工程规范**沉淀下来：当需要**新建**某概念/算法/定理的教学演示工具、**复现**已有工具、或**扩展**新演示时按本规范执行。

**学科无关**：勒贝格积分、康托尔集、中心极限定理、智能优化算法、化学分子、物理场……都适用。换学科只换 core 的领域逻辑，不换工程结构。

## 项目放置位置

- **演示工具放对应学科的 `personal/demos/` 下**：`assets/{subject}/personal/demos/<demo>-tool/`（如 `assets/实变函数与泛函分析/personal/demos/lebesgue-riemann-demo/`）。
- 每个工具一个独立子目录，**独立可运行**（不互相依赖）。
- 新增工具 → 在对应学科 `personal/demos/` 下建目录，并在该学科 `personal/README.md` 登记一行（工具/演示/状态）。
- 非演示类工具（脚本/分析，如学习画像）才放 `tools/`。

## 技术栈（默认）

- **Streamlit**（交互界面）+ **Plotly**（实时绘图）+ **NumPy/SciPy**（计算）
- 依赖写入各工具 `requirements.txt`（如 `streamlit>=1.28`、`numpy`、`plotly`、`pandas`）
- 默认技术栈追求**零前端构建、开箱即用**；若对视觉质感有更高要求（3D / 创意动画 / 网页知识图谱），改用**拓展 C：浏览器端可视化**（three.js / p5.js / d3.js）替代，而不是改用其他 Python 包装层。

## 工程结构（强制）

```
assets/{subject}/personal/demos/<demo>-tool/
├── README.md            # 工具说明：演示什么、结构、参数、画布、状态
├── main.py              # 入口：Streamlit 应用（st.set_page_config + 各模块装配）
├── requirements.txt     # 依赖清单（streamlit/numpy/plotly/pandas…）
├── 启动<工具名>.bat     # Windows 双击启动：streamlit run main.py --server.port <port>
├── core/                # 领域核心（纯逻辑，不依赖界面）
│   ├── model.py         # 领域模型/状态类：保存全部演示状态
│   ├── step.py          # 单步推进接口：每次推进一个演示单元
│   └── <domain>_specific # 领域特有模块（见「学科拓展」）
├── ui/                  # 界面层（只做展示与交互，不写领域逻辑）
│   ├── visualization.py # 画布：实时绘制演示过程
│   ├── sidebar.py       # 控制面板：参数控件/按钮/状态区
│   ├── analysis.py      # 结果分析：统计输出/对比
│   └── help_content.py  # 帮助面板：概念/算法说明文本
└── utils/               # 工具层（实验/批处理）
    └── experiment.py    # 多次运行实验、统计对比、导出
```

### 启动 bat 规范（Windows）

```
@echo off
cd /d "%~dp0"
streamlit run main.py --server.port <port>
pause
```

- 每个工具一个 `启动<工具名>.bat`，端口各工具错开（如 8501/8502/8503…）。
- 工具目录内 `README.md` 说明：装依赖（`pip install -r requirements.txt`）、运行（`python main.py` 或双击 bat）、扩展。

### 运行方式（强制）

- **GUI 运行**：`streamlit run main.py`（或双击 `启动<工具名>.bat`）。
- **无界面运行**：core/utils 用相对导入，必须**从工具根目录**用模块方式：
  ```bash
  python -m core.step        # 无界面验证
  python -m utils.experiment # 实验
  ```
  不能 `python core/step.py`（相对导入会报 `ImportError`）。
- **Windows 控制台编码**：每个 `__main__` 块开头必须加 UTF-8 输出（否则打印中文/`²`/`μ` 报 GBK 错误）：
  ```python
  import sys
  try:
      sys.stdout.reconfigure(encoding="utf-8")
  except Exception:
      pass
  ```
- **README 写对命令**：无界面验证一律写 `python -m core.xxx`。

## 分层规则（强制）

1. **core 层零界面依赖**：领域模型只接收参数、返回结果，不 import 任何 UI 模块；界面层调用 core、core 不反向依赖 ui。
2. **ui 层零领域逻辑**：界面只负责参数收集、调用 core、绘制结果；公式/迭代/判定一律在 core。
3. **utils 层可复用 core**：实验脚本 import core 的模型做批量运行，不经界面。
4. **参数面**：界面侧栏暴露的参数与 core 模型构造参数一一对应。

## 演示要素（每个工具 core 必须实现）

1. **状态对象**：保存当前演示的全部状态，供界面逐帧读取绘图。
2. **单步推进接口**：`step()` 或 `run(step_callback)`——界面按帧调用，每次推进一个演示单元，回调暴露中间状态。
3. **结果输出**：最终结果、关键中间值、历史序列（供结果/对比面板）。
4. **可复现**：可传入 seed（若涉及随机），保证实验可复现。

## 数值正确性（防采样近似错误，强制）

> 教学演示常依赖数值采样近似，但对**"测度为 0 的稠密点集"**（如有理数）等特殊情形会失效。必须规避：

1. **采样点覆盖特殊点**：若演示对象含"稠密但测度 0"的点集（如有理数），采样点必须**显式包含**这些点（如分母 ≤ 某阈值的所有有理数），不能只用均匀 `linspace`——其点可能恰好全落在被漏判的分母上（如分母 1999 的点被只识别分母 ≤ 199 的逻辑漏判为 0）。
2. **解析值覆盖**：凡数值采样会误导的函数（狄利克雷、Thomae 这类在测度 0 点集上取特殊值），积分/结果必须用**解析值覆盖**，不依赖采样近似。
3. **测度加权 ≠ 点数加权**：勒贝格积分按**测度**加权，采样点近似按**点数比例**加权；对测度 0 点集，点数比例会高估，必须用解析值。
4. **对照真值验证**：每个函数对照解析真值核对（如 x²→1/3、狄利克雷→0、Thomae→0），数值偏差超阈值即视为未完成。

## 界面要素（每工具 ui 必须实现）

1. **实时画布**：可视化每次推进的当前状态（概念图/曲线/几何/路径等）。
2. **函数/对象表达式展示**：UI 上必须把当前演示的函数/对象用数学表达式写出来（如 `f(x)=x²`、`f(x)=狄利克雷函数`、`X~N(0,1)`），让学生明确知道正在演示什么；切换函数时同步更新。
   - **注意**：`st.latex` 会自动用 `$$...$$` 包裹，传入的表达式**不能自带 `$` 定界符**（否则变 `$$$...$$$` 渲染失败）。若数据里存的是 `$...$` 包裹的公式，先 `.strip("$")` 再传。
3. **参数侧栏**：全部关键参数控件 + 开始/暂停/重置按钮。
4. **结果面板**：关键结果/统计（与画布同屏或 tab 切换）。
5. **帮助面板**：概念/算法原理简文 + 参数含义 + 操作说明（`help_content.py`）。
6. **判定语义与当前状态一致**：UI 展示的判定/结果必须与用户**当前看到的演示状态**（步数/参数/切分）语义一致；若存在"当前状态"与"极限/最终状态"的差别（如康托尔集：属于当前步 C_n 但不属于极限集 C），必须**同时显示两者**并明确提示差异（如"第 k 步被挖去"），避免用户困惑。

## 实验对比（utils/experiment.py）

同一演示不同参数/不同 seed 多次运行：输出各次结果、均值、标准差等统计；支持导出 CSV，供教学演示参数敏感性结论。跨工具对比由各工具分别运行后人工对照。

## 验收标准（生成完成后逐条核对）

1. `main.py` 可独立启动 GUI，无 import 错误。
2. `requirements.txt` 齐全，`pip install -r requirements.txt` 后能跑。
3. `启动<工具名>.bat` 存在且双击可启动（Windows）。
4. core 层可在无界面环境单独运行（脚本调用 step 循环跑完）。
5. 界面实时绘图不卡顿（每帧计算 < 100ms，或用异步/降帧）。
6. 可复现（涉及随机时，固定 seed 两次运行结果一致）。
7. 结果面板有值（演示至少推进若干步才允许结束）。
8. 帮助面板覆盖：概念/算法原理、全部参数含义、操作步骤。
9. 已在对应学科 `personal/README.md` 登记（工具/演示/状态）。
10. **数值对照真值**：每个演示对象对照解析真值核对（见「数值正确性」），偏差超阈值即未完成。

## 自检审查流程（生成后强制，按序执行）

> 生成/修改演示工具后，必须按以下顺序自检，**全部通过才算完成**（不只是"能跑"）。

1. **语法/导入**：`python -c "import ast; ast.parse(open('main.py',encoding='utf-8').read())"` 或直接 import 各模块，无语法/导入错误。
2. **core 无界面运行**：从工具根目录 `python -m core.step`、`python -m utils.experiment` 跑通。
3. **数值对照真值**：每个演示对象对照解析真值（见「数值正确性」），偏差超阈值即失败。
4. **性能**：UI 高频调用路径（滑块/逐帧/成员判定）单次计算 **< 100ms**；超阈值需优化（降采样 / 缓存 / 降 n / 换算法）。
5. **UI 渲染**：无界面用 Agg 后端调用 `render()` 生成 Figure，不报错。
6. **依赖/启动**：`requirements.txt` 齐全、`启动<工具名>.bat` 存在。
7. **登记**：已在对应学科 `personal/README.md` 登记（工具/演示/状态）。

## 学科拓展（通用核心之上）

> 通用规范（上文）不变；学科/算法专属内容作为**拓展**，按需挂载。

### 拓展 A：算法演示（智能优化，源自 edudemo）
- 适用：ACO / GA / PSO / SA 等优化算法
- core 特有：`test_functions.py`（Rastrigin/Ackley/Sphere）、`tsp_problems.py`、`selection.py`/`crossover.py`/`mutation.py`、`topology.py`、`annealing.py`/`cooling_schedules.py`/`neighborhood.py`
- 额外要素：**收敛判定**（迭代上限 + 适应度停滞阈值）、**收敛曲线面板**（迭代 × 最优适应度）
- 验收补充：收敛曲线有值（迭代至少推进 10 步以上才允许结束）

### 拓展 B：学科演示（按学科挂载）
- 实变泛函：勒贝格积分 vs 黎曼积分对比、康托尔集构造、简单函数逼近
- 概率论：CLT / 大数定律（见 `assets/概率论与数理统计/personal/demos/clt-demo/`）
- 各学科要做的演示工具清单 → `rules/subjects/{subject}/demo-spec.md`（可选）

### 拓展 C：浏览器端可视化（three.js / p5.js / d3.js）——高视觉质感进阶

> **定位**：默认 Streamlit 技术栈追求零前端构建、开箱即用，但视觉质感有限。当演示**需要更高视觉表现力**时（3D 立体、艺术化动态、精致网页知识图谱），用本拓展替代默认技术栈。**默认优先，除非明确要"更炫的视觉"**。选择结果须在工具 `README.md` 与对应学科 `personal/README.md` 中标注技术栈（`streamlit` / `browser`）。

### 技术栈选择（按需三选一）

| 库 | 强项 | 适用 |
|----|------|------|
| **three.js** | 3D / WebGL、光影、粒子、立体 | 立体几何、分子结构、物理场、三维坐标系等必须 3D 的场景 |
| **p5.js** | 创意编程、艺术动态、上手最快 | 过程性教学动画：分形、几何变换、随机模拟、粒子系统 |
| **d3.js** | 数据绑定 + 力导向图、像素级定制 | 精致数据图表、知识图谱 / 学习画像网络图（节点=文章、大小=链接度） |

- 三者可混用（如 d3 做图谱 + three 做 3D 节点），但每工具按需引入，避免依赖臃肿。

4. **参数面**：界面的参数控件与 core 模型构造参数一一对应。

### 演示要素 / 数值正确性 / 界面要素

**完全沿用上文**（状态对象、单步推进接口、结果输出、可复现；采样点覆盖特殊点、解析值覆盖、测度加权、对照真值；实时画布、函数表达式展示、参数侧栏、结果面板、帮助面板、当前状态与极限状态区分）。这些是本 skill 的**教学正确性核心，跨技术栈不变**，浏览器端同样强制。

### 运行方式（浏览器端）

- **GUI 运行**：`npm install` → `npm run dev`（或双击 `启动<工具名>.bat`）→ 浏览器打开 Vite 提示的本地地址。
- **无界面运行**：core 层从工具根目录用 Node 模块方式：
  ```bash
  node src/core/step.js        # 无界面验证
  ```

### 与默认技术栈的差异提醒

- 原 Python 强制结构中的 `requirements.txt`、`python -m core.step`、`启动<工具名>.bat`(streamlit) **不适用于本拓展**；以本拓展的 `package.json` / `src/` / `node` 结构为准。
- 换用浏览器端会引入 Node 环境与前端构建成本，**仅当明确追求更高视觉质感时采用**；普通演示仍走默认 Streamlit。
