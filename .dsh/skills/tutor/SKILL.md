# Tutor — 通用讲解与教学辅助

> 通用讲解/教学 skill，**学科无关**。当前用于数学/统计课程，但流程与质量约束不限于数学。

## 激活条件

当用户请求涉及内容讲解（概念教学、定理推导、例题讲解、复习时的讲解、章节/主题深度学习）时激活。

## 与文章类型的关系（核心）

> 不同类型的文章有不同的结构，但**都遵循同一个 tutor**（本 skill 的通用讲解流程与质量约束）。

| 部分 | 位置 | 内容 |
|------|------|------|
| **通用讲解流程** | 本 skill | 知识脉络教学法 + 讲解质量约束 + 教学模式 + 动作库 |
| **类型结构** | `rules/core/asset-spec.md` | 10 类文章的具体骨架 |
| **模板** | `templates/` | 可直接套用的 md 骨架 |

**写作任何学习类文章时**：先按类型取结构（asset-spec），再按本 skill 的通用流程与质量约束填充内容。类型结构决定"长什么样"，本 skill 决定"怎么讲"。

## 模式选择

开始讲解前先定模式（用户未声明时默认纯讲解模式）：

| 模式 | 触发词 | 产出 |
|------|--------|------|
| **纯讲解模式**（默认） | 「讲一下 X」「解释一下 X」「这个定理怎么证」 | 单点概念/例题讲解，四层管线 |
| **教学模式** | 「进入教学模式」「教我这个主题」「生成 XX 章节文章」「复习第 N 章」 | 主题级学习文章（单文件，概念地图→预算→叙事→动作→检验） |
| **讲解包模式** | 「给这篇论文做个讲解包」「把 XX 拆成讲解包体系」「给读者/队友做技术讲解」 | 一套讲解包体系（多文件，供他人快速理解复杂对象） |

三种模式共享四层管线与讲解质量约束；教学模式额外携带结构层（元数据/预算/动作/检验），见「教学模式」节；讲解包模式面向**他人理解复杂对象**（论文/章节/主题/方法），见「讲解包模式」节。

## 讲解前置（强制 checkpoint，先于一切讲解）

> **任何实质学习话题（讲解/讨论/出题/作业），开始前必须先建 checkpoint 快照 + commit**（防中途丢失，可回 git 检索）。这是硬性前置，不是可选项。
> 纯闲聊 / 操作指令 / 一句话澄清不建 checkpoint；判定见 `rules/core/decision-trees.md` §1。

```
识别实质学习话题/知识点
  → 立即建 _checkpoints/{文章名}.md（草稿文章，标注 10 类类型）
  → git commit "[TOPIC <文章名>][OPEN]"
  → 才开始讲解（讨论/起草都在 checkpoint 内）
  → 学生离开？→ checkpoint 保持 OPEN
  → 学生回来 → git log --grep "[TOPIC" 找未闭合话题 → 恢复讲解
```

- **先于讲解**：实质话题一出现就建，不等讲解完、不等学生说"加入资产"。
- **快照内容**：`_checkpoints/{文章名}.md` 记录文章骨架与当前理解，讲解推进时可持续更新。
- **沉淀资产时**：每次回复最后一句二选一收尾「这段讨论，收进资产，还是继续往下聊？」→ 收进资产则按 asset-spec 写入 **`personal/`**（seed 只读，不得写入）；继续则保持 checkpoint。

### 新对话先查话题（强制）

> 开启新对话时，先查 git 记录确认没有"开了没闭"的话题（按文章名）。

```
开启新对话
  → git log --grep "[TOPIC"   # 列出 OPEN/CLOSE
  → 有 OPEN 且无 CLOSE 的话题？
    ├─ 是 → 列出文章名
    │     → 询问学生：继续讲解 / 收进资产（升级）/ 关闭
    │     → 处理后才开始新话题
    └─ 否 → 正常开始
```

> 决策树见 `rules/core/decision-trees.md` §5·5。

## 讲解质量约束

- **先定义再使用**：任何新符号、新概念必须在使用前给出明确定义，不得默认学生已认识；每个符号同时标明自然语言读法（如 $\forall$ 读作"对任意"，$\exists$ 读作"存在"，$\subset$ 读作"包含于"）
- **每步有"因为"**：推导的每一步都说明理由；先符号后数字，代入时标注具体数值
- **多视角**：用几何解释代数概念，用代数解释分析概念，用物理直观理解抽象
- **核心洞察收束**：讲解结尾用一句话收束核心思想
- **防跳跃**：讲解末尾标注可能需要展开的概念点（供后续追问）
- **反例强制**：定义之后给正反例；定理条件不可少的反例必须给出

## 知识脉络教学法 (Knowledge Pipeline)

一切章节教学遵循四层管线：**整体认知 → 来龙 → 主体 → 去脉**。

### 第一层：整体认知与框架

在学习任一科目的具体章节之前，先建立学科全景：

1. **学科史背景**：什么时代、什么核心问题驱动了这门学科的产生
2. **发展脉络**：学科如何演变，关键人物与转折点
3. **当代应用**：如今在科学、工程、经济等领域如何被使用

### 第二层：章节知识讲解

每一章的知识讲解严格按三个子步骤展开，顺序不可跳过：

#### A. 来龙 (Origins & Motivation)

在展示任何正式内容之前，先建立"为什么要学这个"：

| 来源 | 说明 | 示例 |
|------|------|------|
| **类比已知** | 连接到学生已有的知识 | "这和你在线性代数中学的特征向量是同一类思想" |
| **解决新问题** | 旧知识无法解决的问题，如何启发新概念 | "柯西需要一种方法计算有孤立奇点的积分" |
| **理论/应用需要** | 理论缺口或实践需求 | "为了量化测量误差，我们需要概率空间的理论" |

来龙部分无需用户交互，由讲解者主动铺设。

#### B. 主体 (Core Content)

主体内容的讲解。遵循以下约束：

- **逻辑顺序**：理清定义和定理的产生顺序——哪个先出现，哪个依赖哪个
- **跨学科理解**：用其他领域的视角解释本领域概念（如用几何解释代数、用物理直观理解抽象）
- 遵循「讲解质量约束」中的全部规则

#### C. 去脉 (Applications & Extensions)

主体内容讲完后，展示知识的延伸价值：

1. **当代具体应用**：这个知识在现代解决什么具体问题，如何被使用
2. **跨领域解读**：这个知识能否用来理解其他领域或学科中的问题
3. **高层视角**：更高观点的理解与相关进阶内容（示例：Taylor 展开 → Laurent 展开 → 留数定理 → 实积分计算）

## 例题讲解模式

### 若在当前章节教学流程中
- 例题应嵌入 主体 部分的讲解中，在讲完相关定理后立即展示
- 目的是巩固理论理解，不是孤立练习

### 若作为独立讲解请求
1. 先简要说明本题属于哪个知识体系（来龙，1-2句话）
2. 复杂内容写入临时 md 文件并用 VS Code 打开
3. 用分步推导：原始信息 → 公式代入 → 计算结果 → 结论
4. 每个计算步骤标注具体数值（示出代入的"因为"）
5. 结尾说明本题所用方法可以延伸到什么场景（去脉，1-2句话）

## 教学模式（主题级深度学习）

> 定位：面向**用户自己**的主题级深度学习。输入一个主题/章节，输出一篇「主题学习文章」（单文件，不叫讲解包）——不是单点问答，而是一片知识的完整教学。
> 内容骨架仍复用知识脉络教学法（整体认知→来龙→主体→去脉）；教学模式在其上增加结构层：元数据 → 预算 → 引擎 → 动作 → 检验。

**激活**：用户说「进入教学模式」「教我这个主题」「生成 XX 章节文章」「复习第 N 章」等。

**流程五步，顺序执行**：

### 第一步：概念地图

列出主题内全部概念并标注元数据：

```
概念 | 重要度(核心/支撑/背景) | 难度(基础/进阶/困难) | 前置依赖 | 后续应用
```

### 第二步：讲解预算分配

按元数据决定每个概念的篇幅——「困难的知识单开一节讲来龙去脉」是预算规则的自然结果，不是特殊待遇：

| 元数据 | 篇幅 | 形态 |
|---|---|---|
| 核心 + 困难 | 一整章 | 单开完整来龙：历史/失败尝试/关键转折/多视角/推导全程/易错点/自测题 |
| 核心 + 基础 | 标准四层 | 整体认知→来龙→主体→去脉 |
| 支撑概念 | 一段 | 定义 + 一个例子，带过 |
| 背景概念 | 一行 | 脚注级，「这是为了……」 |

### 第三步：讲解包引擎

- **主线叙事**：先回答「这个主题解决的中心问题是什么」，再逐步构建 → 整合 → 应用；
- **依赖展开**：主体推进中遇到前置缺失概念 → 自动插入该前置概念的概要层（支撑档）再继续，不中断主线；
- **输出形态**：一个主题一篇单文件文章（章节化），结构见 `rules/core/asset-spec.md` §四（章/节）。

### 第四步：教学动作库与切换策略

**动作库**（推进教学的动作，不再只有「讲解」）：

| 动作 | 干什么 | 适用 |
|---|---|---|
| 讲解 | 建立直观与框架 | 概念初遇 |
| 推导 | 证明一遍，展示逻辑链 | 定理/命题 |
| 演绎 | 一般原理应用到具体实例，逐步计算 | 算法/计算技巧 |
| 例题 | 完整走一遍标准问题 | 应用训练 |
| 对比 | 并列相似概念找差异 | 易混概念 |
| 反例 | 展示定义/定理的边界 | 定义之后（强制，非可选） |
| 追问 | 苏格拉底式提问暴露理解 | 检验 |
| 检验 | 自测题/讲给别人听 | 每包结尾 |
| 总结 | 一句话收束核心思想 | 每包结尾 |

**按概念类型的默认动作序列**：

- 定理 → 讲解动机 → **推导**（证明走一遍）→ 例题应用；
- 定义 → 讲解 + 正例反例 + 边界情况；
- 算法/构造 → 讲解 → **逐步演绎**（最小实例手动走一遍，每步标「因为」）；
- 计算技巧 → 例题模仿 + 变式训练。

**按学习者状态的切换**：

- 卡在直觉 → 换视角/类比；
- 卡在推导 → 放慢、逐步演绎、每一步补「因为」；
- 卡在应用 → 先例题模仿再变式；
- 似懂非懂 → 回到来龙，或追问一个能暴露误解的问题。

**主动建议权**：切换不等用户开口，主动给出建议及理由——「这个定理建议推导一遍，因为它的证明手法后面还会用到三次」「这里建议你亲手算一遍，我停在这步等你」。

### 第五步：检验回路

- 每包结尾强制自测题（3-5 题，含伪装成应用陷阱的题）；
- 验收标准：**明天能把这个主题讲给别人听**；
- 检验结果回填学习者状态，驱动下一步动作选择与后续包的前置检查。

### 示例骨架：中值定理章文章

1. **概念地图**：Rolle 定理（核心/基础）、Lagrange 中值定理（核心/进阶，前置=Rolle）、Cauchy 中值定理（支撑）、微分中值定理的应用（核心/基础）；
2. **预算**：Lagrange 单开整章（含来龙：Rolle 与 Lagrange 时代的动机、几何直观）；Cauchy 一段带过；
3. **主线叙事**：中心问题「导数信息如何反推函数整体性质」；
4. **动作序列**：讲解动机 → 推导 Rolle → 由 Rolle 演绎 Lagrange → 例题 → 对比三定理条件差异 → 反例（条件不满足时结论失败的例子）→ 自测；
5. **检验**：一道伪装成中值定理应用的陷阱题（端点条件不满足）。

## 讲解包模式（Explain-Pack Mode）

> 定位：把一个**复杂对象**（论文 / 章节 / 主题 / 方法 / 项目）拆成一套**讲解包体系**（多文件），供"没深入做过但需要理解"的人快速建立整体认知并深入。
> 与「教学模式」的区别：教学模式服务**自己学习**（一个主题一篇单文件文章）；讲解包模式服务**他人理解复杂对象**（一套体系，多文件）。两者命名不同、互不干扰，内容骨架都复用知识脉络教学法（整体认知→来龙→主体→去脉）。

**激活**：用户说「给这篇论文做个讲解包」「把 XX 拆成讲解包体系」「给读者/队友做技术讲解」等。

**输出**：一套按编号命名的讲解包（**不是单文件**）：

- `00-整体认知.md`（全局，1 个）：对象是什么、解决什么问题、整体结构/路线图、阅读地图（各主题文件与共用方法文件的对应表）
- `01-背景与动机.md`（全局，1 个）：来龙——为什么需要它、旧方法/旧理解的局限
- `02-主题N.md`…（每主题一个，编号 02 起递增）：该主题的整体认知/来龙/主体/去脉
- `M-xx-方法-<方法名>.md`（每个方法一个，编号 M-01 起递增）：方法讲解，被多个主题共用；首次用到该方法的主题生成时创建，后续主题直接引用「详见 M-xx」

**与普通讲解的区别**：
- 受众是"要理解但没深入做过"的人（读论文的、队友、读者），不是复习的学生。术语可以出现，但每个术语首次出现必须给一句自然语言解释。
- 必须包含**可直接引用的结论句示例**（2-3 句），并标注哪些说法是过度承诺、不能写。
- 迷你算例必须能体现"数字从哪来"：给 1 个最小实例，手动走一遍输入→处理→结果的流程。
- 必须包含「延伸指引」节：指出可进一步深入的方向、相关材料/前置知识，供读者按需深入。

**分两段生成（与主体内容分离）**：全局包（00/01）先建，供读者尽早建立整体认知；分主题包在主体内容定稿后单独生成。讲解包自身设门禁（人类审阅通过后才可交付）。两段独立，保证各部分质量。

### 示例：论文讲解包

1. **00-整体认知**：这篇论文解决什么问题、核心贡献、方法路线图、阅读地图；
2. **01-背景与动机**：旧方法局限、为什么需要新方法；
3. **02-问题建模**：问题如何形式化（来龙→主体→去脉）；
4. **03-方法/算法**：核心方法逐步演绎（每步标「因为」），迷你算例体现"数字从哪来"；
5. **M-01-方法-XX**：被多个主题共用的方法单独成包，供引用；
6. **延伸指引**：可进一步阅读的文献、可复现的实验、未解决的开放问题。
